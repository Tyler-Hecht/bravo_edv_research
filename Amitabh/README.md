# Heat Index Generation Pipeline

Computes daily, population-weighted heat index by HHS region, for any
year, from NASA POWER weather data. Built to extend CDC's published
heat index series (which currently ends in 2022) forward to whatever years
a study needs, using the same formula and aggregation method CDC's own
data is built on.

If you're a future student picking this up: this package is
self-contained and only contains what's needed to generate data, using
one method throughout. There is no alternate mode or legacy option inside
this package; everything here implements the same hourly procedure
described below.

## What this does

1. For every US county (50 states + DC), pulls a full year of hourly
   temperature and relative humidity from NASA POWER.
2. Computes heat index at every hour, and takes each day's value as the
   maximum across that day's 24 hourly results. This matches CDC's own
   documented procedure for its historical heat index product (CDC builds
   its version from NLDAS-2 data using the same hourly-then-maximum
   approach; this pipeline uses NASA POWER as a data source instead, since
   NLDAS-2 access is a separate integration this pipeline doesn't include).
3. Averages county values up to a state-day value (unweighted mean).
4. Combines state values into a region-day value, weighted by each state's
   2020 Census population.

Output is a 3-column CSV (`HHS Region`, `Date`, `Region_Weighted_Heat_Index`)
matching CDC's own published file's schema exactly, so it can be
concatenated directly with CDC's historical data or dropped into existing
analysis code expecting that format.

## Requirements

R packages: `httr`, `jsonlite`, `dplyr`, `tidyr`, `lubridate`, `readr`, `sf`

```r
install.packages(c("httr", "jsonlite", "dplyr", "tidyr", "lubridate", "readr", "sf"))
```

No API key needed. NASA POWER's API is open.

## How to run

1. Open `R/generate_heat_index.R`.
2. Edit the `YEARS` line near the top, e.g. `YEARS <- c(2026)` or
   `YEARS <- c(2023, 2024, 2025)`.
3. Run the script: `Rscript R/generate_heat_index.R`.
4. Output lands at `output/generated_heat_index.csv`.

**Timing**: roughly 35-40 minutes per year (one NASA POWER API call per
county, ~3,108 calls/year, about 0.7 seconds each). Every call is cached
to `cache/power_hourly/` as it completes, so an interrupted run resumes
without re-pulling anything already done, and re-running for a year
that's already been generated is instant.

**Then, verify the output**: open `R/verify_output.R`, point
`GENERATED_FILE` at what you just produced, and run it. It checks
completeness (every region has every expected day) and bounds (no
negative or implausible values). If the year you generated is one CDC has
also published (through 2022), you can additionally point
`CDC_REFERENCE_FILE` at CDC's file and it will report bias/RMSE/MAE/
correlation per region. This is the only real accuracy check available,
since years without CDC data have no ground truth to check against.

## Methodology, in full

**Formula**: the NWS "modified Rothfusz" heat index regression, a core
regression (calibrated on hot/humid conditions) plus a simpler linear
estimate for milder conditions, plus two small corrections at extreme low
and high humidity. See `heat_index_formula.R` for the full derivation and
an important open item: the exact branch thresholds match the standard
published NWS algorithm, but have not been confirmed line-by-line against
CDC's actual internal implementation. If you validate a new year against
CDC data and see a systematic mismatch, this is the first place to check.

**Hourly-to-daily**: heat index computed independently at every hour from
that hour's own temperature and humidity, day's value = maximum of the 24
hourly results. This matches CDC's own documented procedure for its
historical heat index product.

**County -> state (Eq. 2)**: plain, unweighted mean of county heat index
values within a state.

**State -> region (Eq. 3)**: population-weighted average of state values,
weighted by each state's total population.
`HI_region = sum(HI_state * Population_state) / sum(Population_state)`

## Known limitations

- **Alaska and Hawaii are excluded.** This matches the coverage of CDC's
  own historical product (built from NLDAS-2, which is limited to the
  contiguous US) but is a real gap if a study needs those two states.
  Extending coverage would need an antimeridian-aware fix for Alaska
  (its counties span across the 180th meridian) and a populated-area-only
  boundary for Hawaii (Honolulu County's official boundary includes a long
  chain of largely uninhabited islands, which would distort an
  area-weighted average). Neither is built here.
- **Each county is one sample point, not an area average.** NASA POWER's
  hourly API only supports single-point queries, unlike its daily/regional
  API. A point-vs-area comparison on a small sample found roughly a 1
  degree Fahrenheit difference, real, but small relative to the accuracy
  gained from the hourly-max method itself.
- **The Rothfusz branch thresholds are the standard published NWS
  algorithm, not confirmed against CDC's actual source code.** See
  `heat_index_formula.R`'s header for the full disclosure.

## A note on validating a new year

There is no way to directly verify accuracy for a year CDC hasn't
published; that's the nature of the gap this pipeline exists to fill. The
way to build confidence in this method is to re-run it for a year CDC
*has* published (through 2022) and confirm it reproduces CDC's real
numbers closely, using `verify_output.R`'s `CDC_REFERENCE_FILE` option.
If that check still holds for the year(s) you actually care about's
underlying climate conditions, that's the basis for trusting the new
year's output, not anything this script can check directly.
